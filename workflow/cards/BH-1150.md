## 问题现象

用户在第三方电子签平台已完成签署、合同已归档，但我方后台仍显示签约中、还错误提示摄像头未绑。只能人工调后门接口补回合同号、手动推进到已签约才修好。

## 背景

合同签署后，我方系统需要主动回查第三方拿到合同号写回自己的库；后续的签署完成回调要按合同号反查本地记录，才能推进签约完成态和快照更新。

## 根本原因

回查第三方时远程调用超时了，捕获异常的代码把超时直接当成了查到了但没数据，静默返回、既不回写合同号、也不重试或告警。而实际上第三方那边合同早已创建成功。合同号没回写，后续签署完成回调按合同号反查本地记录就失败，签约完成态和快照更新都不触发。超时是结果未知，代码却把它当成了确定的无数据。

```java
// 问题版：把超时/异常和真的没数据混为一谈，静默返回空
try { return openApi.query(sourceCode); }
catch (Exception e) { return null; } // 调用方拿到 null 就不回写、不重试、不告警
```

## 解决方案

区分调用失败和确认无数据：超时或调用异常是结果未知，要重试或标记为可恢复失败并告警，绝不能当成 null 静默返回；给回写关键字段的链路加重试和最终失败告警，并给第三方已成功但本地未回写的情况加对账补偿。

```java
try { return openApi.query(sourceCode); }
catch (RpcException e) {
    log.error("回查合同调用异常，需重试或告警", e);
    throw new RetryableException(e); // 结果未知，交给上层重试或标记失败并告警
}
```

## 测试建议

专门造下游超时或抛异常的场景，断言数据不会被写成空、会触发重试或告警、状态不会停在中间态。也要覆盖第三方已成功但我方未回写的数据不一致场景，验证有对账或补偿能自愈。

## 经验总结

外部依赖一定会偶发超时，你的代码怎么对待超时才决定它会不会变成线上故障：超时是结果未知，要重试加告警，绝不能当成确认无数据静默吞掉。
